  METHODOLOGY — تجمیع روش‌های تحقیق (بازتولیدپذیر)
  Consolidated: 2026-09-27 | منابع: گزارش‌های v5، SESSION4/5/6، DISCOVERIES
═══════════════════════════════════════════════════════════════════════════════

این فایل «چطور انجام دادیم» را یکجا جمع می‌کند. هر روش: چه می‌کند، ابزار،
پیش‌نیاز، و تله‌های شناخته‌شده.

───────────────────────────────────────────────────────────────────────────────
 M1 — UNPACKING با امولاسیون Unicorn (لایه اول: لودر VMP)
───────────────────────────────────────────────────────────────────────────────
  هدف: رمزگشایی سکشن‌های VMProtect در حافظه بدون اجرای واقعی باینری.
  ابزار: Python + unicorn 2.1.4 + capstone + pefile (اسکریپت‌های unicorn_unpack.py
         / dll2_unpack.py / emu_v2.py در session های قبلی).
  روش:
    1. PE را در 0x140000000 مپ کن (لودر) / 0x180000000 (DLL).
    2. DLLهای سینتتیک بساز (synthdlls.py) با EAT کامل kernel32/MSVCP140/ws2_32/...
       — پروlogue واقعی ویندوزی داخل محدوده ماژول، تا IAT resolve شود.
    3. محیط وفادار: TEB/PEB/LDR، KUSD @0x7FFE0000 (KdDebuggerEnabled=0)،
       DR0-7 صفر، CPUID GenuineIntel بدون بیت hypervisor.
  ۱۴ لایه‌ای که باید پاس شود (خلاصه — جزئیات: گزارش v5 بخش ۲):
    L01 IsDebuggerPresent | L02 NtQIP(0x1E)=STATUS_PORT_NOT_SET (نه SUCCESS!)
    L03 NtQIP(0x1F) معکوس | L04 HideFromDebugger | L05 NtQSI(0x23) KernelDebugger
    L06 integrity فایل از طریق NtOpenFile+NtCreateSection+NtMapViewOfSection
    L07 NtProtectVirtualMemory (رمزگشایی واقعی همین‌جا اتفاق می‌افتد)
    L08 IAT rebuild | L09 CPUID | L10 RDTSC (۳۳۸ سایت، دومرحله‌ای)
    L11 KUSD | L12 DRx | L13 NtQSI(0x0B) لیست ماژول‌های کرنل | L14 UOI_FLAGS
  تله‌های طلایی (اینجا خیلی‌ها می‌سوزند):
    • پچ بایت = فعال شدن چک integrity حافظه VMP → فقط register/RIP-skip.
    • KUSD.SystemTime باید High1 == High2 باشد (سه‌فیلدی KSYSTEM_TIME).
    • سه منبع زمان (KUSD/FILETIME/QPC) باید همسو و پیشرونده باشند — فریز = فیک.
    • NtMapViewOfSection: چک کن SEC_IMAGE (0x1000000) — اگر SEC_COMMIT بود،
      مپ باید خطی/خام باشد نه ردهاترها در RVA! (کشف ۵ session4)
  خروجی: image آنپک (final_FULLIMAGE.bin) با .text ~85% / .rdata ~98% decode.

───────────────────────────────────────────────────────────────────────────────
 M2 — FORWARD-MITM (شنود پاسخ واقعی vendor بدون دستکاری)
───────────────────────────────────────────────────────────────────────────────
  هدف: گرفتن پاسخ «واقعی» سرور vendor (افست‌ها + امضا) بدون ریپلی/فیک.
  ابزار: fake_server.py --forward + hosts (api.bestcheatir.com→127.0.0.1)
         + CA فیک تراست‌شده + explicit DNS 8.8.8.8 برای IP واقعی vendor.
  روش: چیت → TLS ما → رله verbatim به vendor (SNI محفوظ، سرت واقعی verify)
       → پاسخ را همان‌طور برمی‌گردانیم و در offsets_capture_<ts>.json ذخیره.
  تله‌ها:
    • امضای پاسخ per-request (nonce-bound) است — ریپلی capture قدیمی روی
      پچ‌نشده fail می‌شود.
    • خروجی capture همیشه برای auto-load سرور فیک قابل استفاده است.
    • XAMPP/هر چیز روی 443 باید بسته باشد (دو بار گیر کرده).

───────────────────────────────────────────────────────────────────────────────
 M3 — CRACK آفلاین امضا با brute-force روی capture ها
───────────────────────────────────────────────────────────────────────────────
  هدف: استخراج فرمول امضا بدون devirt کردن کد VMP.
  ابزار: brute_force_sig.py — HMAC-SHA256 با secret معکوس‌شده، فضای
         subset/permutation روی فیلدهای پاسخ.
  پیش‌نیاز: secret (از آنپک: تابع 0x140065760) + چند capture واقعی
            (هرچه بیشتر، تأیید محکم‌تر — ما ۸ تا داشتیم).
  نکات: secret را اول روی فرمت «درخواست» sanity-check کن (فرمتش شناخته بود:
        key|hwid|app_id|app_version|timestamp|nonce) بعد فضای پاسخ را بگرد.
        نتیجه: "true|LOGIN_SUCCESS|server_time|expires_at|hwid|nonce".
        server_time رشته است نه epoch؛ success به‌صورت "true" رندر می‌شود.
  نتیجه عملی: سرور فیک با امضای معتبر → چیت بدون هیچ پچی کار می‌کند.

───────────────────────────────────────────────────────────────────────────────
 M4 — MEMTAP (خواندن رکوردهای IPC از حافظه لودر)
───────────────────────────────────────────────────────────────────────────────
  هدف: دیدن داده‌ای که DLL از شبیه‌ساز به لودر می‌فرستد (بدون هیچ هوک).
  ابزار: memtap.py — ReadProcessMemory روی heap لودر، اسکن رکوردهای 0xBB0.
  کلید موفقیت:
    • چیت فوکوس باشد (unfocused = رکوردهای خالی/صفر).
    • داخل مچ باش (لابی = فریم خالی).
    • الگوی رکورد: marker +0x460 ("player"/"Matrix")، id +0x4A0،
      counter +0x4A8، dist +0x514، name +0x51A، ماتریس +0x55C.
    • ولیدیشن ماتریس: norm ردیف چرخش ≈ 1.0 (sخت‌گیر نکن — live فرق دارد).
  یافته معماری: رکوردها با WPM از MuMuNxDevice پوش می‌شوند؛ لودر هیچ read
  syscall ای ندارد (ProcMon اثبات) — یعنی کانال push-only است.

───────────────────────────────────────────────────────────────────────────────
 M5 — کرک آفلاین پروتکل بدون devirt (روش تصمیم‌گیری)
───────────────────────────────────────────────────────────────────────────────
  ترتیب تلاش برای هر «چک پنهان»:
    1. رشته‌های مسیر تصمیم را در دامپ آنپک پیدا کن → xrefs → تابع تصمیم.
    2. اگر تابع در ناحیه decode شده بود → capstone مستقیم.
    3. اگر رمز بود → به‌جای devirt، بایت‌های واقعی همان نقطه را در
       امولاسیون (demo_accept_any_key.py) با ورودی کنترل‌شده اجرا کن.
    4. اگر تصمیم روی داده محیطی بود (مثل امضا) → brute-force فرمول از روی
       جفت‌های واقعی (M3).
  این ترتیب باعث شد بدون شکستن چک نهایی VM، کل پروتکل باز شود.

───────────────────────────────────────────────────────────────────────────────
 M6 — تحلیل live حافظه بازی از بیرون (adb root + /proc/pid/mem)
───────────────────────────────────────────────────────────────────────────────
  ابزار: driver/cheat_chain_verify.py و driver/typeinfo_decode.py (نوشته‌شده).
  پیش‌نیازها و تله‌ها:
    • بعد از هر ری‌استارت شبیه‌ساز: adb connect 127.0.0.1:16384 + adb root
      (root همیشه از دست می‌رود!).
    • MuMu بدون UI: MuMuManager.exe control -v 0 launch (پوشه nx_main).
    • بازی باید در حال اجرا باشد (libunity مپ شده باشد) و برای دوربین/بازیکن
      باید داخل مچ بود (لابی = دوربین خالی — طبیعی است، skip نکن).
    • IsValidPtr چیت (ptr-0x1001)<=0x7fffffffeffd کلاس‌پوینترها را هم پاس
      می‌کند — برای آبجکت‌های heap بازه 0x78.. لازم است.
    • ساختار کلاس IL2CPP این بیلد scramble است (klass->name خوانده نمی‌شود)
      — پس شناسایی کلاس فقط از روی کد استفاده‌کننده ممکن است.
